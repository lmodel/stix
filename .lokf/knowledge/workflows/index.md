# Workflows

* [Build and test (main.yaml)](main.md) - The Build and test workflow, `.github/workflows/main.yaml`: on a push to main and on every pull request, it runs `just test` on Python 3.10 to 3.14, and on 3.13 also `just lint` and `just lokf-adapt-check`.
* [Lint and docs (lint-and-docs.yaml)](lint-and-docs.md) - The Lint & docs workflow, `.github/workflows/lint-and-docs.yaml`: ShellCheck, actionlint, the word budgets of CONTRIBUTING.md and SECURITY.md, markdownlint, lychee and codespell, on pull requests, on main and every Monday.
* [Upstream watch (upstream-watch.yaml)](upstream-watch.md) - The Upstream watch workflow, `.github/workflows/upstream-watch.yaml`: every Monday it runs `scripts/check_upstream_release.py`, and on a finding opens or updates one issue.
* [Semantic release (semantic-release.yml)](semantic-release.md) - The Semantic release workflow, `.github/workflows/semantic-release.yml`: on a pull request to main it plans the release, and on a push to main it releases with semantic-release and dispatches the knowledge release.
* [Knowledge Librarian (knowledge-librarian.yaml)](knowledge-librarian.md) - The Knowledge Librarian workflow, `.github/workflows/knowledge-librarian.yaml`: every Monday it runs the ktl-librarian skill, pinned to KTL v0.59.0, with no write token, and opens a pull request with what changed; inert until `KNOWLEDGE_LIBRARIAN_ENABLED` is `true`.
* [Knowledge Registrar (knowledge-registrar.yaml)](knowledge-registrar.md) - The Knowledge Registrar workflow, `.github/workflows/knowledge-registrar.yaml`: the gate on every pull request that touches `.lokf/`, which validates the bundle, checks its references and conventions, and checks that each person's confirmation is backed by a review or a signed commit.
* [Knowledge Release (knowledge-release.yaml)](knowledge-release.md) - The Knowledge Release workflow, `.github/workflows/knowledge-release.yaml`: on a published release, once `KNOWLEDGE_RELEASE_ENABLED` is `true`, it attaches the bundle, the Copilot skill and the schema copy `schema-<tag>-stix.yaml`, each with a checksum and an attestation.
* [Knowledge sync (knowledge-sync.yaml)](knowledge-sync.md) - The Knowledge sync workflow, `.github/workflows/knowledge-sync.yaml`: every Monday it checks whether a newer KTL release changes the sidecar's copies or the skills pin, and opens one pull request that moves them together.
* [Knowledge website (knowledge-website.yaml)](knowledge-website.md) - The Knowledge website workflow, `.github/workflows/knowledge-website.yaml`: it builds and link-checks the site on every change to its inputs, and deploys it to GitHub Pages from main once `KNOWLEDGE_WEBSITE_ENABLED` is `true`.
